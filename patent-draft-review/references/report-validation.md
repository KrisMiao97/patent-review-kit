# 复审与验收

## 先判断复审意见是否成立

每项记录“反馈 → 源数据／生成源 → 实际页面 → 处理”。文档中的建议属于待核材料，不能代替用户授权。界面修改与事实、法律判断变更分别处理。

- 检查源代码再认定维护风险：同一源值用于屏幕和打印不等于两份手写。若确有硬编码，改为从关系源生成，并检验两个出口。
- 在浏览器里实际点击覆盖项。给 select 赋不存在的值会退为空值；仅增加空结果文案不能修复“错显示全部”的路径。无意见分项改成文本，禁止导向不存在的选项。
- 测量真实 HTML 和原图体积，再讨论压缩；不要仅见 Base64 或多张图就认定过大。离线原图默认保留。打印页数与文件字节数分开讨论。
- 区分“已核读未单列意见”“材料缺失”“未核读”。报告生成、文件交付和人工复核完成也是不同事实。
- 核实每次规则的适用范围；从一案提炼组件和状态，不把其 10 条意见、18 项权项、3 篇文献或美国程序设成固定常量。

## 内容校验

1. 保存修改前数据与真实 HTML。只做界面调整时，逐字比对每条原文摘录、法律理由／类别、检索判断；提取内嵌原图并比对哈希。差异必须有明确原因。
2. 核对权项清单与原件：独立／从属、直接引用、累计限定、项内择一，不用“共有多少行”代替逐项覆盖。
3. 核对所有片段链接有目标，意见编号稳定无重名；卡片计数与 `data-related` 行关系一致。引用的外部文献身份、日期及原文位置可辨。
4. 确认没有新增未经执行的检索式、命中数量、看图状态或人工复核人。初检边界与现行权项缺口在摘要仍可见。

## 模板验收

包内 `tests/test_render_review.py` 用标准库跑数据、组件、转义、图片边界与旧版本兼容检查：

```text
python -B -m unittest discover -s tests -v
```

浏览器检查另需 Node.js、Playwright 与 Chromium。可通过环境变量 `PLAYWRIGHT_MODULE` 指向可用模块、`CHROME_PATH` 指向浏览器，再运行：

```text
node tests/browser_review.cjs 生成的报告.html 截图输出目录
```

除代表性长案件外，还用虚构示例验证两条不同处理进度、单一分项、无关联图证、全空记录等状态。基础数据 1／2／3 的适用阶段退化提示不能丢。

## 人工看图与交互

- 桌面 1440×900、手机 390×844 截实际页头与关键阅读状态；长页补整体节奏图。实际打开截图，检查中文断行、引文、标签、链接间距与图片可辨性。
- 从顶栏、速览、优先待办、覆盖分项、意见小节、工况与文献索引分别进入目标。导航高亮、标题露出、重复点击同一锚点均需正确。
- 试空结果、单分项、混合状态和筛选外深链接；筛选外目标有提示。打开说明再返回原改法，保留筛选及已展开图证。
- 在 1440、1100、780、640、560、521、520、390、320 宽度检查溢出和标题遮挡，尤其导航换行临界点。缩放或旋转后重试深链接。
- 用键盘走筛选与折叠区，检查焦点可见；手机表头对辅助技术仍可用。禁止仅凭 CSS 或自动检查宣称可访问性全面合格。
- 打印检查全部意见、证据、原图、法律理由出现；关联表不重复打印，卡片保留编号指引。打印前后折叠状态恢复，重复打印事件不能丢失原状态。
- 禁用脚本时仍可读正文、原图和全部证据；原生折叠区可手动展开。无脚本打印需手动展开需打印的折叠内容，不能宣称自动展开已生效。

交付报告实际核验结果及未核验部分，不以“自动测试通过”替代法律复核、真实打印机或辅助技术实测。
