# 技术问题、方案与效果的因果必查

这是每次功能性专利审稿的必查项，先于文字润色和修改候选。适用于装置、方法、软件、控制、材料和组合方案；“结构”应按案件理解为部件关系、步骤、数据处理、材料组成或控制条件。申请前、审查中及授权后均核查，修改边界另按程序判断。仅涉及外观且不主张功能的材料可说明不适用理由；材料缺失、未检索或时间有限不能当作不适用。

## 先登记问题和权项，再建立对应

1. 从背景技术、发明内容、有益效果及用户目标分别提取问题，保留原句位置。把已公开的结构事实、申请人主张、工程推断和待验证假设分开。用户目标不自动成为权项效果；原稿写了“需要解决”也不能自证问题真实存在。
2. 从权利要求原文独立列出全部独权及其备选路径，在权项速览中填 `claim_type`。以权项速览、独权检索和因果记录交叉核对。未执行检索时也应逐项登记并标为未执行。涉及新增作用的从属路径单列，并保留累计限定。将问题和权项逐项对应，不能只挑已有解决思路的部分。权项原文未取得时，登记具体缺件和影响，不能以不适用结束。
3. 每条对应写清：使用工况 → 故障或待改进现象所在部位／步骤 → 原因 → 当前权项的必要特征 → 特征怎样改变该原因 → 可支持的效果及成立条件。独权和从属项、原稿和候选方案分别核查，不能把从属新增特征、实施例限制或建议加入的结构倒算为原独权已具备。

## 三段依据必须分别核实

| 环节 | 必须回答的问题 |
| --- | --- |
| 问题及原因 | 什么对象在什么工况下出现什么缺陷？缺陷由哪一结构、步骤或条件导致？文献到底公开了结构，还是也说明了该缺陷？因果推断的前提是否成立？ |
| 方案及作用过程 | 权项具体限定了什么？它作用于故障发生的同一部位、对象、步骤和时间吗？中间作用过程是否缺环节？依赖哪些必要条件？ |
| 效果及边界 | 可推得或已有测试支持的改善是什么？比较基准、适用范围、边界条件和相反证据是什么？局部效果是否被扩大成整体效果？ |

每个环节记录可复核位置、原文或数据，以及它实际支持什么。证据种类使用原文事实、工程推断、测试结果、待验证假设。原稿中的效果句只能证明其提出了该主张，不能循环证明效果成立。没有依据时直接记录缺口，不补造文献、试验、故障发生率或产品事实。

不要求所有技术问题都已被现有专利明说，也不一律要求样机测试。能够由已确认事实和技术原理合理推得的关系，可以标注为工程推断，并写出前提、推理和边界；需要测试才能确定的量化或复杂性能，列明待验证项目。缺少因果依据不直接等于法律上无效、缺乏创造性或不能实施，法律定性另核证据与法域。

## 输入信息、方案选型与效果精度

对每项独权及改变输入、条件或效果的重要从属路径，沿下列三步反查。和本路径无关的单步写明原因。整案是否适用仍按本节开头判断。

1. **区分源输入和方案实际使用的信息。** 核对采集对象、部位、时间和样本粒度，再看方案实际使用的是原始输入、抽样、聚合、转换后的特征，还是间接指标。物料成分、力、温度、图像和运行记录都适用。指出哪种信息能区分待解决的情形，经过转换、合并或截断会丢掉什么。做一次具体反查，比如两种状态有相同输入值但需要不同动作。涉及测量或训练时核对输入与参考真值是否对应同一对象、批次、位置和工况。把结果写入 `scenario`、`cause` 与 `countercheck`。
2. **检查从所需效果回推可实施的选型。** 分开列权项实际允许的输入、结构或处理方法、关键条件、目标输出，并指出说明书明确教导了哪套组合。至少尝试追到一条有据可实施的路径，再看它为何能或不能代表所主张的其他分支。范围较宽时，挑选影响机理的代表性替代或边界，逐一说明输入和方案是否匹配、哪些参数或条件必须随目标调整、原文是否给出选用或排除的依据。分别列出候选部件、算法或材料，本身不足以证明任意组合都能工作。若无法从原文及可核常识选到可行组合，指出缺哪项选择依据以及要试什么，而非只写「没有参数」或要求测试全部组合。把结果写入 `features`、`mechanism`、`limits` 与 `gaps`。
3. **把效果粒度、输出分辨率和实际误差分开。** 先确认声称的是动作完成、定性分类、分档、连续量估计，还是可重复达到的性能。再核计量对象、单位、工况、基准、真值及可比较的误差或稳定性。刻度、位数、网格间距和阈值只表明输出或设定如何表示。由此不能推得精度、最小可辨差或跨工况可靠性。只验证了粗分类、局部样本或某一工况时，列明可支持的效果，逐项说明外推到更细输出、更宽工况或最终系统效果还缺什么。对定性效果，按机理和边界判断所需证据，无需默认索要数值指标。把结果写入 `effect`、`limits`、`countercheck` 与 `gaps`。

例如，设备只记录一段时间的平均载荷时，要核实其是否还能识别会造成损伤的瞬时峰值。工艺列出多种浆料和固化方法时，应查哪种配方与固化窗口确实配合。阀门能按 0.1 mm 步长下指令时，还要区分设定步长、实际位移误差和流量调节精度。例子只示范核查方式。

## 必做的反向核查

- **位置、对象和工况是否一致。** 引文中的缺陷与本方案的作用点不同，须解释两者的传递或关联依据，不能靠相同关键词连接。
- **问题是否被偷换。** 原目标是避免某故障，方案只改善中间现象时，必须证明这个现象如何导致该故障。缩小有益效果可以修正表达，但不证明原问题已解决。
- **必要特征是否在对应权项内。** 暂时去掉仅在从属项、实施例或候选中的特征，再判断独权能支持什么效果。多条择一路径分别判断。
- **最容易失败的条件是什么。** 核查异常、边界、替代解释和副作用；不能将“保持畅通”“完成解锁”“正确识别”等待解决条件直接当成已满足的前提。
- **是否只是替方案寻找理由。** 从背景文献重新还原缺陷，再与方案比对；不因已有图纸、较完整文字或已检索到相似部件就默认发明方向成立。

## 缺口必须影响结论

每条对应标为有依据、部分有依据、关键依据缺失或证据矛盾。说明缺在哪一环、影响哪个权项／效果、应核实什么以及确认后如何处理。独立项或核心效果的未决因果缺口必须列高优先级意见，首页直接显示，不得埋入一般注意事项或附图说明。意见可先采纳，但未补足依据或未明确撤回有关主张前不能标为已解决。

可以交付有明确缺口的报告，不能因此停止全部可做工作；也不能把“报告生成”“条数补齐”“引用一致”写成方案已经通过审查。返稿按原缺口重新核查整条对应关系。若缩小效果、放弃原目标或改变方案，明确记录范围变化和仍未解决的问题，保留旧版本，不能把文字删改冒充补证。

## 通用反例

冷却电机外壳不必然解决轴承润滑失效；降低模型平均误差不必然降低漏报率；增加材料强度不必然提高整个连接部位的疲劳寿命。应分别确认发热或失效部位、评价数据和载荷条件，再说明改进措施能改变哪一步。例子仅用于提示核查方向，不作为任何真实案件的证据。

## 数据和复验

新报告使用 schema 5 的 `causal_review`，字段见 [数据与组件](template-schema.md#因果必查数据)。生成器检查记录覆盖、状态和关联。`critical` 由对具体权项或核心效果的实质影响决定，关联未解决的高优先级意见。输入中漏列的原文权项及技术真实性仍需人工核对。先用通用正反例检验，再用明确版本的实际稿件复验。保存原件摘要值、引用位置、复验意见和未验证部分。已知答案的检验记作定向复验。
