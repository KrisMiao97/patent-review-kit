# Word 批注版与清洁版

批注版和清洁版以同一份有明确版本的 Word 原稿及同一组已采纳改动生成。批注版在改后正文的相应位置附原生 Word 批注，逐条保留问题、原文片段、状态和「补充参考改法」。清洁版使用相同的改后正文。

## 采纳规则

- 只审稿时交专利审核报告，Word 标记为「未要求」。要求审稿并出 Word 时，以核验后的可编辑基线生成两份文档，候选意见只写入批注。要求改稿时，只应用授权范围内已明确采纳、依据已核对且适用于当前阶段的改法。待研发确认、待材料或待选择的内容留在批注和报告。已有返稿中确认解决的项可批注记录，无需再次应用。
- 对同一改动相关的权项编号、引用、说明书、附图及摘要一起核对。改后清洁版仍有未决问题时，在报告列明。没有已采纳正文修改时，注明清洁版正文沿用本轮输入。
- 优先用用户提供的可编辑原始 DOCX。只有 PDF 或扫描件且用户要求 Word 时，转换为可编辑副本并对照原件核验权项全文及编号、说明书段落、公式、表格、附图和图号。记录原件版本、转换副本及差异。转换无法可靠核验时，先交报告并说明 Word 未生成及所缺基线。原始文件已有批注、修订标记或复杂结构时，保留原件，先核对并另存稳定工作副本。

## 导出助手

在可用的工作区 Python 环境运行，需要 `python-docx 1.2` 或兼容版本。

Word 修改清单与 HTML 报告使用不同格式。沿用报告意见编号，把经核验的 Word 段落和唯一片段填入 `anchor`，把改法、条件和同步要求整理为 `reference_fix`。只有符合采纳规则的改法才设置为 `adopted` 并按 Word 基线编写正文操作。

```text
python scripts/export_review.py 原稿.docx 修改清单.json --annotated 修改后_批注版.docx --clean 修改后_清洁版.docx
```

清单示例：

```json
{
  "source_sha256": "填写本轮原稿文件的64位SHA256",
  "issues": [
    {
      "id": "R-05",
      "problem": "权3仍使用推杆，与权1中的顶杆叫法不一致。",
      "reference_fix": "核实为同一部件后，将权3的推杆改为顶杆。",
      "anchor": {"paragraph": 7, "quote": "所述推杆的端部设有斜面"},
      "status": "adopted",
      "edits": [{"paragraph": 7, "before": "所述推杆的端部", "after": "所述顶杆的端部"}]
    }
  ]
}
```

段号从 1 开始，按 Word 主正文顶层段落编号，包含标题和空段。原文片段需在该段唯一出现。每条意见填写非空 `reference_fix`。状态为 `adopted`、`pending`、`rejected` 或 `resolved`。只有 `adopted` 的 `edits` 会进入正文，其他状态的候选保留在清单，导出时不执行。新增段落可用 `{"paragraph": 7, "before": "定位到原段落的唯一片段", "insert_after": ["新增的从属项全文"]}`，同时核查编号和后续引用。

助手面向主正文普通文本段落，能保留原稿中未涉及的内容。需要直接修改表格、文本框、公式、插图或跨段结构时，按原稿结构使用文档工具处理，然后验证两份改后正文一致。出现定位歧义、重叠或来源版本变化时，先修正清单。批注锚定段落，批注内容附可核对的原始片段。若改法会删空某段，将意见锚定到仍保留文字的相关段落，并在问题描述中指明被删段落。

交付前检查源稿指纹、改后正文、Word 批注内容和锚点、清洁版批注及修订标记，以及附图、编号和段落样式。渲染并看页图，区分结构验证与视觉验证。
