# 三档改法与组合依据

在涉及保护范围取舍时，以同一份已锁定版本的稿件提出候选方案。先确定法域、程序、现行权项和原始申请材料。报告标明候选方案的用途、适用阶段、范围变化及采纳条件。三档按需要选用，简单文字校订可只用一档。缺乏依据的档位写清缺口及下一步。

| 档位 | 如何形成候选 | 读者需要作出的决定 |
| --- | --- | --- |
| 保守澄清 | 保留已核实的技术关系和引用路径，消除指代、位置、连接或状态歧义。逐项检查措辞调整是否实质增减限定。 | 哪些表达可以在现有依据下写得更明确。 |
| 平衡限定 | 将有依据且对解决问题有作用的配合关系加入相应权项。列出放弃覆盖的结构、产品影响及仍需验证的效果。 | 为获得更明确的区别，愿意接受哪些范围限制。 |
| 收窄后备 | 给出可单独审阅的完整候选从属项，或包含全部必要限定的独立项替代稿。列明直接引用和累计继承路径，展开择一分支。 | 在较宽方案受挑战时，哪套有据可查的具体组合值得保留。 |

三档可以针对不同权项。说明哪些是互斥替换、哪些可以并存，以及各自基于原权项还是另一候选项。不要把“更窄”直接写成“有创造性”，新增限定后重核现有技术、实际产品和保护作用。借鉴分层选择的方法，以本案原件独立形成文字，不复制第三方 Skill 或示例权项。

候选填写 `candidate_check`，注明完整独立项、完整从属项或局部措辞，以及实际核读结果。收窄后备必须给出并核对完整权项，不能用“略”或待补文本占位。完整性由逐句核读确认，不用特定语言或句式的正则表达式代替判断。

用 `scope_check` 分别记录范围是否改变、理由、放弃覆盖的结构及产品影响。已确认增加或删除实质限定的方案不列为保守澄清；尚不能确定时明写范围待核。逐项填写 `claim_actions` 的保留、替换、新增或删除及理由。更宽的原从属项与增加组合限定的后备项可以并存，不因包含相同特征而自动删除原项。候选基于另一候选时，采纳前须整理累计限定并重新给出完整文字。

## 每条后备权项怎样证明组合

1. 保存完整候选文字与原权项路径。把继承特征和本次拟加入的特征分开编号，组合重要的继承关系也要进入对照表。
2. 对每项特征分别给出说明书段号及句首锚词、逐字摘录、图号及部件标号。无段号时使用页码和句首。图示证据记录实际可见关系，未核读或未画出的细节明确写出。没有附图的案件记下原因，保留文字证据。
3. 另写一段组合理由。指出这些部件或步骤为何属于同一实施例，是否在相同状态下协同，或者在同一实施例的明确时序中先后工作。可用正文的实施例引用、部件标号、动作关系和已核附图相互印证。仅有各个零件的独立出处或同图出现，仍需核对连接和条件。
4. 检查原文中的可选、替代和互斥关系。兄弟从属项分别从属于同一独权，只能证明各自路径，组合使用还要找到正文或附图的联系。跨实施例时给出明确的组合指引和适用条件，缺少指引就保留为依据缺口。
5. 列明同一实施例中候选项省略了什么，以及为何可省略。检查遗漏的特征是否与拟提取结构或效果不可分，是否改变原来状态、因果或参数关系。不得只摘出有利特征后忽略其必需条件。
6. 检查反证和矛盾，包括图文冲突、连接未画清、互斥位置、不同材料或工况。分别记录“组合记载是否有依据”和“实施方式及效果是否充分”，有组合记载也可能仍缺实施细节。

结构化记录时，将权项路径放入特征的 `claim_source_ids`，将正文／图证放入 `source_ids`。每个标为有依据的组合相关特征都要有对应正文或图证，不能仅在组合层加入一段无关说明书。来源的相关性仍须核读原文；程序识别不了贴上正确类型标签的无关文字。

为实际实施方式建立稳定编号 `embodiments[].id`，来源和组合通过 `embodiment_ids` 关联。共用正文或附图可以保留全部适用编号，并用于其中一个实施例的候选。`same_embodiment` 表示同一编号内的结构配合或明确时序。

跨实施例的 `explicit_combination` 须在 `guidance_source_ids` 中列出原文指引。用每条来源的 `combination_guidance` 写清原文允许哪些实施例的哪些特征一起使用，以及适用条件。各条指引须将所选实施例连成一组。若指引通过中间实施例相接，还要核对两段原文在该例中允许采用的特征和条件是否一致。将原件明确互斥的方案记入 `embodiment_conflicts`，并按证据保留部分支持或缺口。

每条候选的来源表与组合说明共同构成可复核记录。使用 `amendment_options` 字段生成报告，读者可从特征跳到原文证据，再返回候选。

## 适用阶段和缺口

申请前可以建议补充真实的研发交底。新增内容经确认后形成新版本，在报告中保留来源日期。审查中必须逐项回到原始提交文本及相关组合判断修改依据。阶段未知或授权后先核可用程序。原始申请材料缺失时，当前草稿支持只说明当前版本的记载情况。

组合状态使用“有依据”“部分有依据”“依据有缺口”“待核验”。“有依据”必须列出全部核查特征的出处、同一实施例或明确组合指引、必要条件和省略分析。程序检查来源类型、逐特征对应、实施例编号及已记录冲突等结构关系；实质判断仍需逐字回看原件。引用动作段时，区分所引用的安装或运动关系与该段适用配置的前提；省略前提结构须给出可分理由及相应依据。

对于缺少联锁、阈值或故障动作的稿件，可解释补充交底的方向。不得把已画出的传感器直接扩写成自动控制闭环。候选文字保留清楚的适用条件，待确认内容只进入意见及补证清单。
