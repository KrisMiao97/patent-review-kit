# 专利审核报告输出设计规范

更新：2026-11-10。适用：离线 HTML 报告；Word 的修订规则另见 `references/word-output.md`。

## 方向与来源

- 阅读对象是项目负责人和专利复核人员，先了解范围与待办，再逐条查证。报告采用蓝白配色、紧凑正文和证据优先的阅读顺序。（用户确认）
- 当前任务是把已认可报告沉淀为可复用模板；不重启视觉方向探索。（用户确认）
- 本规范按 oil-ui-pro v0.33.3 的内容浏览与规范沉淀方法整理；通用化判断单独标明来源。（Agent 推断）
- 用户授权依据为本轮“根据聊天记录优化该 skill，并制定输出设计规范和模版”，此前多轮确认修改与保留内嵌原图。（用户确认）

## 品牌资产

- 无客户标志、商用字体或专有插画；不得虚构客户背书。（Agent 推断）
- 原始附图属于核查证据，保留图号、页码、比例和可读性；不以装饰图替换。（用户确认）
- 不把当前案件的申请人配色或名称做成全局品牌。（Agent 推断）

## 语义角色

样式与数值唯一来源是 `assets/review-report.css`；结构在 `assets/review-report.html`。（Agent 推断）

- `--bg` 为阅读画布，`--paper` 为正文与控件表面，`--ink` 为主要文字。（Agent 推断）
- `--muted` 用于来源、位置和辅助说明，仍须有可读对比；不得用来淡化法律限制。（Agent 推断）
- `--blue` 用于标题、入口与链接；`--soft` 用于建议改法、表头等需识别的区域。（Agent 推断）
- `--line` 组织章节与记录；不靠每行交替底色拆散同一权项的证据组。（用户确认）
- 优先级和判断标签均有文字，颜色只能补充含义；不同状态维度分开。（用户确认）
- 中文正文用系统字体；数字和意见编号用等宽数字特性，英文引文优先按词换行。（Agent 推断）
- 标题、正文、出处三级清晰；关键字段标签不能比正文显著弱。有限阅读宽度避免长行。（用户确认）
- 圆角和边框沿用组件；不增加装饰性渐变、阴影、图标或进入动效。（Agent 推断）

## 内容与章节

- 页头显示审核版本、阶段、报告修订、立场与法域等已知信息；人工复核未知时明确写“未指定，待复核”。（用户确认）
- 章节序列由 `scripts/render_review.py` 中的章节集合一次定义，导航名称与正文标题一致。（用户确认）
- 顺序为概览、可选技术与路径、意见、权利要求对照、附图与原图、可选工况、现有技术、范围与交付。（Agent 推断）
- 概览先结论再优先待办与缺口；结论可按审核依据、产品比对、文本问题、检索限制拆段，但不得为凑四段虚构内容。（Agent 推断）
- 稳定编号不等于排序；待办按处理顺序列，解释编号用于关联。（用户确认）
- 权项速览必须有明显入口；只保留权项、类型及引用、意见编号。详细技术要点放路径区，原文放证据区。（用户确认）
- 声明速览覆盖的范围，未列关联意见不能表述成无风险。全篇适用问题可单独链接。（用户确认）
- 先用完整中文说明部件安装位置、触发情况、动作和作用；术语首次出现解释，保留事实条件。（用户确认）

## 可用组件

- `.overview`：结论与待办并列，窄屏顺序排；阅读说明和权项速览位于概览内。（用户确认）
- `.issue`：编号与优先级 → 摘要 → 原文与问题 → 关联图证 → 改法 → 可展开的法律依据。（用户确认）
- `.legal`：折叠时仍露出法律判断类别，展开后显示理由、来源和返回摘要入口。（用户确认）
- `.stage-note`：在候选文字之前写适用程序及限制；不把关键条件藏进跳转目标。（用户确认）
- `.related`：只显示显式关联的记录，屏幕和打印计数均从同一关系源生成。（用户确认）
- `.matrix`：保留每行的权项及路径；同项多行靠组边界识别，不使用合并单元格削弱窄屏上下文。（用户确认）
- `.review-gallery`：离线内嵌 PNG/JPEG 原图，配图号及来源，桌面多列、手机单列。（用户确认）
- `.coverage-row`：有意见才链接筛选；无意见显示文字及材料／核查原因。（用户确认）
- `.delivery-table`：交付项、文件交付、人工复核、说明分别成列。（用户确认）
- `.search-scope`：检索公共范围只写一次；窄标签列配宽说明列。独权表使用与数据相符的表头。（用户确认）

## 跳转、筛选与可访问性

- 只有实际存在于数据中的筛选值才进入选项；只有一个值的维度可隐藏，但全篇处理进度须能看见。（用户确认）
- 深链接显示被筛选隐藏的目标并标明原因，保留其他筛选与展开状态；再次点击同一目标仍可展开。（用户确认）
- 阅读说明保留指向来源改法的显式返回链接，不使用可能离开报告的通用后退按钮。（用户确认）
- `--nav-height` 根据导航实际高度测量并随视口变化更新；各类锚点共用偏移规则。（用户确认）
- 控件和链接有键盘焦点；原生表格保留表头语义，手机附加标签对辅助技术隐藏以免重复。（Agent 推断）
- 手机不横向挤压密集表格，转成带标签记录；短“权／图／PDF”引用由生成器统一处理换行。（用户确认）
- 无脚本仍能阅读全部报告、打开原生折叠区和查看完整证据表；不展示无法工作的筛选工具。（Agent 推断）

## 打印与离线

- 保留原文、全部法律理由及独立证据表；打印省去每卡重复的证据表，保留数量及编号指引。（用户确认）
- 打印前展开阅读说明、路径和法律依据，打印后恢复原展开状态；过滤不造成漏印。（用户确认）
- 原图按纸张限制缩放，每页图保留比例；页数是内容取舍，文件字节数另行实测。（Agent 推断）
- 不用外部字体、运行库、统计脚本或远程图片；外部专利／法规链接只是来源入口。（用户确认）

## 样板与实现入口

- `examples/template-input.json`：虚构的种苗箱案例，演示填写与不同处理状态，不用于真实法律判断。（Agent 推断）
- `examples/example-report.html`：由该示例数据及同一生成器生成的离线样板，实际数值以 CSS 为准。（Agent 推断）
- `references/template-schema.md`：字段到组件的映射，不允许在数据中直接嵌入自定义 HTML。（Agent 推断）
- `assets/review-report.js`：筛选、证据关联、导航与打印状态；不要在每案另加一套脚本。（Agent 推断）

## 验收和不要做

- 以 `references/report-validation.md` 核对桌面、手机、关键交互和打印；自动检查不能代替看实际截图。（Agent 推断）
- 不把初检写成完整无效或 FTO 结论，不把公开权项标成现行权项，不虚构检索命中数、复核人或完成状态。（用户确认）
- 不按截图猜源代码维护风险，不仅因 HTML 出现重复数字就认定手写；先检查生成源。（用户确认）
- 不把单案条数、图号、引用路径或法域固化成全局模板；不靠渲染后字符串替换拼装报告。（Agent 推断）
- UI 修订不改原始摘录、法律判断或证据状态；确需更正时作为内容变更单独记录与核验。（用户确认）
- 不为消除空筛选制造虚假的“无问题”结论，不为压短页面删除关键条件。（用户确认）
